- Bugs found and fixed during this slice:
  1. `_iso_duration_to_min()` crashed with `AttributeError: 'list' object has no attribute
     'strip'` on persianpot.com, which emits `totalTime`/`prepTime`/`cookTime` as a one-item
     list of free text rather than an ISO-8601 duration string. Fixed by coercing through the
     existing `_first()` helper before parsing (same pattern S17 used for `recipeYield`).
     Covered by `test_fetch_sites_duration_list_coerced`.
  2. `sitemap_locs()` returned nothing for justonecookbook.com's sitemap URLs in browser mode:
     Yoast serves a human-readable HTML table (not raw `<loc>` XML) at the same URL when the
     request carries a full-browser `Accept` header, so the existing `<loc>` regex found
     nothing and the crawler silently fell back to a homepage-link crawl (52 URLs instead of
     ~1,400). Fixed with a same-host `<a href>` fallback when no `<loc>` tag is found.

- Design was wrong about: the brief says "It keeps one browser context per site, 1 page per
  2 seconds, and respects robots.txt." All three hold as implemented, but robots.txt itself is
  fetched with the plain `fetch()` even for a browser-mode site, not the browser — every
  browser-mode site's robots.txt (checked: justonecookbook.com) has been reachable with a plain
  GET, so this is simpler and doesn't cost an extra browser page-load per site. Flagging it as
  a deliberate simplification rather than a gap, since it wasn't explicit in the brief.
